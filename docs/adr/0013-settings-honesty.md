# ADR-0013：设置页只保留真正生效的项

- **状态**：已采纳
- **日期**：2026-10-19
- **关联**：ADR-0011（Web UI 与 Emby 对齐）、ADR-0012（首页 Hero）

## 背景

Serata 的设置页是从 Emby 4.9.5 的运行时 dump（`emby495-settings-*.md`）1:1 搬过来的结构，
每个页面「看到什么控件就照抄什么控件」，控件全部绑到 localStorage。
搬的时候是**形似优先**，没有问一句「这个开关后面有谁读」。

一次核查（`grep localStorage.getItem` 全量对照 `setItem`）暴露出真相：

| 写入方 | 读回方 |
|---|---|
| 6 个用户设置页各自 `watch(store, ...)` 写 `serata.*Settings` | `useTheme` 读 `serata.themeMode`；`HomeView` 读 `serata.homescreenSettings` 的 7 个槽位 |

也就是说 **约 50 个控件里只有 2 组真正影响界面**。其余（音频语言、字幕模式、字幕文本大小、
时区、启动行为、文本大小、屏保、隐藏已播放媒体、电视模式主页面……）改完存盘，然后永远没人读。

同时侧栏里有 3 条 `route: null` 的条目（播放 / 通用 / 键盘和遥控器，属 Emby Web 的本地设置组），
点击处理器写成 `item.route && router.push(item.route)` —— 有 hover、有焦点、能点，**但什么都不发生**。
用户的原话是「设置页有好几个选项点击不进去」。

## 决策

1. **假控件一律删掉，不标注「即将支持」**。一个存得下、改了没反应的开关，比缺失更伤：
   它消耗用户的信任额度，而且日后会被当成「已经做过了」。
2. **侧栏只渲染有路由的条目**。`route: null` 的死按钮从数据里删掉，并在渲染层加兜底
   （`visibleAdminSections` 过滤空路由、丢弃空分组），任何人再塞 null 都不会变成死按钮。
3. **能救的就救活，而不是删掉**。语言下拉原本也是摆设（`setLocale()` 全项目零调用点），
   而 i18n 早已会读 `localStorage['serata.locale']` —— 补一个 `watch` 就变成了真功能，
   于是保留并接线，同时删掉没有语言包的「日本語」（选它只会静默回落英文）。
   接线的代价是它立刻暴露出下一层欠账：**侧栏和字段名都切成英文了，下拉选项还是中文**。
   根因是选项数组写成模块级常量（`const TZ_OPTIONS = [{ label: '自动(系统)' }]`），
   切语言后不会重算。规则：**任何出现在模板里的选项文案都必须走 `computed(() => t(...))`**。
   本页 6 组选项（时区/启动行为/文本大小/图像大小/屏保/音效/退出菜单）已改为 computed，
   补 17 个键；语言名本身（简体中文 / English）按惯例保持各自语言书写，不翻译。
4. **空壳页整页删除**（通知页全文 42 个字符，没有数据源）。

## 本轮删减清单

- 侧栏：删除「Serata Web 设置」整组（3 条死按钮），删除「通知」条目 → 29 条变 25 条；
  `/settings/notifications` 路由与视图一并删除（未匹配路径由 `/:pathMatch(.*)*` 兜底回首页）。
- 显示页（9 → 1 项）：删 播放音频时的背景样式 / 首选电视节目显示 / 自动打开文件夹视图中的单个项目 /
  隐藏未观看剧集的剧透信息 / 「在以下页面中隐藏已播放的媒体」三项；保留 外观三选 + 强调色说明。
- 主页面（9 → 7 项）：删 电视模式主页面 / 显示详情预览；保留 7 个真生效的区块槽位。
- i18n：同步删除 28 个不再被引用的键（脚本按「完整点号串在 src 下零命中」判定，zh/en 两侧一致，345 = 345），
  并为选项文案补 17 个键（362 = 362）。
- 语言开关验收：切到 English 后侧栏、页标题、字段名、**全部下拉选项**均为英文，
  配置页仅剩 4 个汉字（就是「简体中文」这个语言自称），`<html lang>` 与 `serata.locale` 同步。

## 后果

- 设置页不再是「Emby 的形状」，而是「我们真的做了什么」。后续每加一个设置项，**必须同时落读取方**，
  否则不算完成。
- 仍有 4 组摆设未处理（用户本轮明确保留）：播放页、字幕页、配置页的时区/启动行为/文本大小/屏保、
  主页面「媒体库顺序」拖拽（`onDrop` 只改内存数组，不落库也不被 HomeView 使用）。
  它们在下一次动设置页时按同一标准处理。
- 管理后台的 section 页（转码/网络/数据库/转换/电视直播）走的是后端真字段接口
  `GET /System/Configuration/Fields`，属「真但可配项少」，不属于本 ADR 的删除对象。
- 6 个插件详情页共用同一份写死的假字段（启用插件/服务地址/同步间隔），属于同一类问题，
  但涉及插件机制，单独处理。
