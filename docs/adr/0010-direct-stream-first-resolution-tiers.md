# 转码哲学：直传为默认路径，质量档位按分辨率而非码率

与 Emby 分歧两处：其一，产品推荐姿态是**流式直传**——DirectPlay 优先，DirectStream（remux）次之，转码仅作为设备能力不足的兜底，不做"默认就转"。其二，质量档位**按分辨率划分**：原画 / 1080p / 720p / 480p / 360p，客户端报最大档位，服务器按档位出流；每档的 ffmpeg 映射（编码器、预设、像素格式、HDR→SDR tone mapping 默认 bt2390）为内置推荐值，管理员可自定义覆盖。Emby 的码率分档与默认映射参数不抄。

## Considered Options

- 照抄 Emby 码率档位与参数：客户端体验不直观（用户不知道"12Mbps"意味着什么），且其默认 tone mapping 效果差。
- 转码为默认路径：把最贵的路径当常态，性能对标无从谈起，也是用户抱怨卡顿的根源。

## Consequences

- 转码子系统仍按此前决定完整进 v1（含 GPU、字幕烧录、HLS），只是它在正常使用里应当很少被触发——兼容矩阵里 PlayReport 会如实上报 DirectPlay 占比，作为"直传优先"是否达成的度量。
- 档位名与分辨率写死在 SPEC，扩展档位走配置而非代码。
- 转码是**可选能力**：管理员可配置为"禁止转码、只允许流式直传"（此时能力不足的客户端收到明确拒绝而非转码流）。
