# Emby 迁移：已校对的元数据是 Canonical 的种子，不是待重刮的废料

用户在 Emby 里的元数据是人工校对过的事实（含大量手动修改与锁定字段），重新刮削等于洗掉心血；且 MoviePilot 等生态工具围绕 Emby 数据结构工作。决定：迁移工具读取 Emby 的 `library.db`（SQLite），**按文件路径匹配**将 Item 元数据整体导入为本地 Canonical 条目的种子；Emby 的锁定字段原样保留，**AI 仲裁永不覆盖锁定字段，只能填空**。NFO/海报本为文件，直接复用；用户账号迁用户名，密码重置；观看进度/已看/收藏按路径匹配迁入。

## Considered Options

- 元数据重刮（先前立场）：错误。会把用户的校对成果全部洗掉。

## Consequences

- 导入数据在仲裁体系里的地位高于 TMDB 原始数据：Canonical 初始值 = 导入值，后续仲裁只补缺、不改写锁定字段。
- Emby `library.db` 无官方 schema 文档，导入工具以实际抓取的 4.8 库文件为准，版本差异记录在迁移分册。
